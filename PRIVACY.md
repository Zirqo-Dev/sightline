# Privacy

This repo is public and published via GitHub Pages. It holds **paper and research data only**.

## Public names rule

Never write the owner's name, handles, emails, or wallets, or any tracked person's real handles or "founder" wording, into any file, desk data, or commit message in this repo. Say "the owner". Use codenames for whales. Raw identities go only in the private repo.

- Never commit owner wallet addresses, stake keys, real holdings, balances, or real transactions.
- Keep those in private bot memory, not in any file here (including notes, headlines, history and followups).
- Third-party research data (token mints, policy IDs, platform/pool addresses, launcher/sniper keys) is fine.
- The whale roster's private file (`whales/roster.json`, wallets and social accounts) must never be committed. `solada-prefilter/whale_roster.json` is the public tally: codename, role, status, scores, and `eligible_for_active` with its reason. No wallets, stake keys, address tags, or handles. The guard rejects a file named `roster.json`, a private roster document, and a public tally that contains a wallet, a handle, or the previous field wording. `eligible_for_active` does not promote a whale. Promotion stays a manual owner decision.
- Run `scripts/privacy-guard.sh` (and `python3 scripts/validate-desks.py` for the format check, workflow `schema-check.yml`) before committing (no arguments = staged files, or all tracked files if nothing is staged). CI (`.github/workflows/privacy-guard.yml`) runs it over all tracked files on every push and PR to `main` and fails the check on any match; the optional `PRIVACY_GUARD_PATTERNS` repo secret adds extra patterns there.
- Identity wording (the owner name, the Discord account used for reads, and the lead whale's social handles) is not written in this repo. `scripts/privacy_identity.py` hashes normalized tokens and 2- and 3-word n-grams with SHA-256, or HMAC-SHA256 when `PRIVACY_IDENTITY_KEY` is set, and compares them to digests. Digests come from the `PRIVACY_IDENTITY_HASHES` secret, a gitignored `.privacy-identity-hashes` file, or `identities/blocked.sha256` in the private repo (fetched with `SIGHTLINE_PRIVATE_TOKEN`, and only when that repo is private). A hit reports a count only. An absent, empty, or malformed digest list fails the guard, including when `PRIVACY_IDENTITY_REQUIRE` is unset. That variable cannot turn the failure into a pass. Wallet rules still run. Normalization, which existing private digests already use: lower case; any character outside letters, digits, and underscore is a separator, so extra whitespace is not hashed and a leading `@` is not part of the token; no extra salt is added. Digests are SHA-256 of that gram, or HMAC-SHA256 when `PRIVACY_IDENTITY_KEY` is at least 16 characters. A shorter key is ignored. Stored digests must stay on that same mode. The lead whale is named by the public codename only.
- GitHub Pages deploys only after that guard and the format check both pass (`.github/workflows/pages.yml`). A failed guard does not publish.
- Add full private addresses as extra patterns locally in `.privacy-patterns` (gitignored, one regex per line) or the `PRIVACY_GUARD_PATTERNS` env var / repo secret (newline separated). Never commit them.
- Platform addresses that must appear in public files (the Solada curve address) go in `scripts/privacy-public-keys.txt`, one full `addr1` per line. The guard masks those exact values in every scanned file. A `stake1` line is rejected. An entry that matches an owner pattern, or whose stake part matches an owner address pattern, fails the guard. Never list the owner's wallet there. Platform-address masking still runs when owner patterns are not loaded, and the guard warns. A stake key is never masked, so a missing owner list cannot publish one. Whole tokens only: a longer id that merely contains an allowlisted address still fails. The lead whale stake key is not in this repo. The prefilter reads `WHALE_STAKE` or, with `SIGHTLINE_PRIVATE_TOKEN`, `whales/lead.stake` or the lead row of `whales/roster.json` in the private repo. Output carries the `w-` tag only. Git history may still contain the old key; rewriting history is the owner's decision. `big_moves.py` likewise skips its run when `PRIVACY_GUARD_PATTERNS` is empty or has a line it cannot read the way `grep -E` does (logs a count only). The whale ledger's state is kept in the private Actions cache, not desk-data. `solada-prefilter/liquidity_moves.json` actor tags, and `solada-prefilter/vetoes.json` evidence tags, are checked the same way as dev_tag: a role label or a `w-` hash. Those tag checks do not use the platform-address mask, so a raw stake key there still fails. Solana forensics reports publish `w-` hashes for dev, owner, buyer, funder, and cluster wallets. Token mints stay. The raw funding cache goes to `forensics/funding.json` in the private repo when `SIGHTLINE_PRIVATE_TOKEN` is set. The rugger blacklist (`rugger-blacklist.json`) holds raw deployer wallets and funding hops in the private Actions cache. Cardano and Solana each have their own cache. Publishing that file, a document with the private shape, or a raw wallet key in `vetoes.json` or `solana-desk/rugger_would_veto.json`, fails the guard. An owner `w-` id in desk-data fails it too, and the log shows a count only. Those public files show an `r-` id (HMAC, 12 hex) when `RUGGER_ID_PEPPER` is set, and no rugger id when it is not. An `r-` id is not a `w-` dev tag. The raw list is pushed to the private repo only when `SIGHTLINE_PRIVATE_TOKEN` is set. Ciphertext is not committed to a public branch. No secret is created in this repo.
