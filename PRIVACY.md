# Privacy

This repo is public and published via GitHub Pages. It holds **paper and research data only**.

- Never commit owner wallet addresses, stake keys, real holdings, balances, or real transactions.
- Keep those in private bot memory, not in any file here (including notes, headlines, history and followups).
- Third-party research data (token mints, policy IDs, platform/pool addresses, launcher/sniper keys) is fine.
- The whale roster's private file (`whales/roster.json`, wallets and social accounts) must never be committed. `solada-prefilter/whale_roster.json` is the public tally: codename, role, status, and scores only. The guard rejects a file named `roster.json`, a private roster document, and a public tally that contains a wallet, a handle, or the previous field wording.
- Run `scripts/privacy-guard.sh` (and `python3 scripts/validate-desks.py` for the format check, workflow `schema-check.yml`) before committing (no arguments = staged files, or all tracked files if nothing is staged). CI (`.github/workflows/privacy-guard.yml`) runs it over all tracked files on every push and PR to `main` and fails the check on any match; the optional `PRIVACY_GUARD_PATTERNS` repo secret adds extra patterns there.
- GitHub Pages deploys only after that guard and the format check both pass (`.github/workflows/pages.yml`). A failed guard does not publish.
- Add full private addresses as extra patterns locally in `.privacy-patterns` (gitignored, one regex per line) or the `PRIVACY_GUARD_PATTERNS` env var / repo secret (newline separated). Never commit them.
- Exact public third-party keys that must appear in config (e.g. the founder whale's stake key) go in `scripts/privacy-public-keys.txt`, one per line. The guard masks only those exact values; an entry matching an owner pattern fails the guard. Never list the owner's wallet there. Hardened after the #26-#28 review: each entry must be exactly one full stake key (`stake1` + 53 chars), masking is off when no owner patterns are loaded (fail closed), only whole tokens are masked, and only in `solada-prefilter/config.json`. `big_moves.py` likewise skips its run when `PRIVACY_GUARD_PATTERNS` is empty or has a line it cannot read the way `grep -E` does (logs a count only). After the #29 re-review the guard also pins every allowlist entry to `solada-prefilter/config.json` `whale.stake`, and derives the stake key from any owner pattern holding a full base address, failing if that key is allowlisted (so a secret that lists only the owner's payment address still protects the owner's stake key). The whale ledger's state is kept in the private Actions cache, not desk-data. `solada-prefilter/liquidity_moves.json` actor tags, and `solada-prefilter/vetoes.json` evidence tags, are checked the same way as dev_tag: a role label or a `w-` hash, and those files are not masked. The rugger blacklist (`rugger-blacklist.json`) holds raw deployer wallets and funding hops in the private Actions cache. Cardano and Solana each have their own cache. Publishing that file, a document with the private shape, or a raw wallet key in `vetoes.json` or `solana-desk/rugger_would_veto.json`, fails the guard. An owner `w-` id in desk-data fails it too, and the log shows a count only. Those public files show an `r-` id (HMAC, 12 hex) when `RUGGER_ID_PEPPER` is set, and no rugger id when it is not. An `r-` id is not a `w-` dev tag. The raw list is pushed to the private repo only when `SIGHTLINE_PRIVATE_TOKEN` is set. Ciphertext is not committed to a public branch. No secret is created in this repo.
