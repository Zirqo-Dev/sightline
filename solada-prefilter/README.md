# Solada prefilter (zero AI)

`prefilter.py` is a numeric screen that runs in GitHub Actions (`.github/workflows/solada-prefilter.yml`) and wakes the Grok Bot desk routine only when something crosses a line. No model calls.

**Inputs:** `https://www.solada.fun/api/launches` and `/api/market` (market can go stale, so on-chain data wins), GeckoTerminal pools (DexScreener fallback), Blockfrost holders/flows (Koios fallback when `BLOCKFROST_PROJECT_ID` is missing or failing), optional Solana `getTokenLargestAccounts` via `SOLANA_RPC_URL` or `HELIUS_API_KEY` (shared deployer ignored).

**Thresholds** are parsed from `solada/paper.json` `rules[]` at run time: rule `k` (min holders, min ADA side), rule `y` (thin-pool ADA side), rule `aa` (zero-holder copycats = noise). Kill lines come from open tickets' `kill_line` numbers and `solada/log.json` `kill_lines` text. Watch-list stake prefixes come from `whale_watch` / `whale_watch_added` in the log and its history. Knobs that are not desk rules (whale thresholds, caps, pacing, units for non-Solada tickers) live in `config.json`.

**Triggers:** a new launch passing k and y; a tracked name newly crossing its kill line; a founder-whale move (2000+ ADA equivalent, 10%+ of a position, any ASCEND/STRIKE change, or a new position) between runs; a watch-list key in a new launch's first block. Each fires once (state in `desk-data:solada-prefilter/state.json`). The first run is a baseline: it records everything as seen and sends nothing.

**Sizing (valuation.py):** on-chain quantities are raw units. A whale move is valued by the ADA (lovelace) leg of the whale's own txs since the last snapshot (handles aggregator buys); only without an ADA leg does it fall back to `raw / 10**decimals x pool price` (decimals from Koios `asset_info` token-registry metadata, else `tokens.cardano.org`; Solada curve launches are 6). Unknown decimals = not sized (never `raw x price`). Buy flags size buyers the same way. DEX LP tokens (Minswap V1/V2, SundaeSwap, WingRiders policies; extend via `config.json` `lp_policies`) are labelled `LP` in `whale.lp_moves` and never count as whale moves, buys, or size flags. Kill lines are deduped through `state.json` `kill_reported`: a kill line re-fires only when its crossed values change (a data gap is not a recovery).

**Webhook:** `POST $SOLADA_WEBHOOK_URL` with `Authorization: Bearer $SOLADA_WEBHOOK_KEY` and `{"reason":"threshold","names":[...],"metrics":{...}}`. Skipped when the URL is not set.

**Schedule:** cron-job.org only (job "Solada pre-filter": `workflow_dispatch` every 2h at :07). The workflow has no GitHub `schedule:`. Kill lines Snek has already marked `hit: ...` in `log.kill_lines` are recorded in state and never sent.

**Kill-line status (SPD-47):** each non-dry run writes `desk-data:solada-prefilter/kill_status.json`, `{ticker: {line, metric, value, hit, first_hit_at, changed_since_last}}` (plus `text`, and `desk_hit` for `hit:` lines), for every tracked name (lines from `solada/paper.json` open tickets and `solada/log.json` `kill_lines`, desk-data first, falling back to main). `changed_since_last` is true when `hit` flips, the hit metric or line changes, or a crossed value moves 25%+ deeper than the last report. A kill-line webhook fires only when `changed_since_last` is true (on top of the `kill_reported` dedupe), so a line that is still hit with nothing moved never re-fires, even if `kill_reported` lost its entry. A data gap keeps the previous `hit` and is not a change.

**Whale sizing (Oct 26 fixes):** a move's ADA leg is used as-is only when the legs' token qty matches the snapshot delta within 5%. Otherwise the delta is valued at the legs' ADA-per-token rate (`value_basis: ada_leg_rate`). Decimals are always resolved, so payloads carry `qty` (whole tokens) next to the raw `delta`. Dust moves (under 25 ADA or under 1 whole token, `config.json` `whale.dust`) get `"dust": true` and no `pct`, so they never trip the 10% position trigger. Curve launches carry `curve_pct`.

**GeckoTerminal:** the free API rate-limits shared runner IPs. Lookups are paced at 3 s, retried on 429 after 6 s and 15 s (Retry-After honoured, capped at 60 s), and cached per unit within a run. After 3 failed lookups the rest of the run uses DexScreener (`config.json` `geckoterminal`).

**Privacy:** the whale is resolved from its ADA Handle at run time; only a short hash tag (`w-xxxxxxxx`) is logged or stored. The full holdings snapshot needed for deltas lives only in the Actions cache (`--cache-dir`); committed state keeps just threshold-crossing moves (tag, asset, amount change).

**Flags (flag-only, `flags.py`):** heuristic whale/cabal signals written to `desk-data:solada-prefilter/flags.json` (`new` = this run, `recent` = last 300) for Snek's daily run. They never count toward rules k/y/aa or kill lines and never fire the webhook alone; when a threshold trigger is already firing, the run's new flags ride along as `metrics.flags`. Each flag fires once (hash in `state.json` `flags_seen`). Thresholds live in `config.json` `flags` (loose defaults); Snek's stake-prefix tags are the seed watchlist in `flags.snek_prefix_tags`, plus `whale_watch` keys from the log.

| kind | fires when (default) |
|---|---|
| `watch_tags_first_block` | 2+ watch tags among the launch's first-block buyers |
| `watch_tags_early_buyers` / `pool_preseeder_early` | any watch tag in the first 20 buyers (pre-seeder called out) |
| `known_launcher_deploy` | `launcherAddress` stake matches a launcher/pre-seeder/founder tag (free, every new launch) |
| `identical_size_buys` | 3+ wallets buy the same size (±1% or ±0.5 ADA) within 600 s |
| `coordinated_buys` | 4+ wallets buy within 120 s, starting within 15 min of launch |
| `stake_key_multi_address` | one stake key buys through 2+ addresses |
| `fresh_wallet_swarm` | 4+ early buyers whose first tx is <= 4320 blocks (~1 day) before the launch |
| `repeat_early_buyer` | same wallet in the first 20 buyers of 2+ launches |
| `sniper_full_exit` | a first-block buyer now holds 0 of that token |
| `koth_pile_in` | curve >= 80%: watch tags or 4+ fresh wallets in the latest 25 txs |
| `user_created_pool` | launch has a pool but no Solada curve |
| `ada_side_drop` | ADA side down >= 20% since last run |
| `holders_down_mcap_up` | holders fall while mcap rises |
| `holders_doubled_ada_up` | positive: holders x2 with a rising ADA side |
| `volume_without_holders` | 24h volume >= 3x ADA side with flat/falling holders (wash) |
| `holder_concentration` / `concentration_jump` | top stake cluster >= 25% of non-script supply / +10 pts (only where holder pages were already fetched) |
| `founder_whale_move` | whale moves that passed the whale trigger, minus COCK/SOLADA team-support noise |

Wallets appear only as `w-xxxxxxxx` (sha256 of the stake key) or as Snek's existing prefix tags. Stake keys are derived from base addresses locally (bech32, no API call). Full keys, wallet ages and sniper positions stay in `--cache-dir/flags-cache.json` (Actions cache). `flags.assert_public` aborts the run before writing any full address or stake key. Cost: at most ~40 Koios calls per run (8 launch scans x 2, 15 wallet-age lookups, 3 KotH scans x 2, 1-2 holdings batches), about 25 s at the configured pace; zero on baseline runs.

Tests (offline, synthetic fixtures, includes a stubbed `--dry-run`): `python3 -m unittest discover -s solada-prefilter/tests`

Local test: `python3 solada-prefilter/prefilter.py --data-dir /tmp/pf --dry-run`

**Big moves (SPD-43, phase 1, `big_moves.py`):** research rows for Snek, never triggers or the webhook. Each non-dry run writes `desk-data:solada-prefilter/big_moves.json` (`moves` kept 72h). A row is any stake key (or a key address with no stake key; DEX pool/script addresses are counterparties and skipped) whose moves into or out of one token within 24h add up to about 5,000 ADA or more, or 10%+ of that token's pool ADA side. Fields: `tag` (10 chars), `ticker` (`LP` for LP tokens), `direction` (`in`/`out`), `ada` (the mover's net ADA across the whole tx, all ADA legs summed), `qty` (whole tokens when decimals are known, else raw; see `qty_basis`), `tx_short`, `time` (UTC), `next_hop` (null; phase 2), plus `window_ada`, `pool_pct`, `lp`, `unit_short`. Tokens scanned: this run's tracked and candidate rows that have a unit, largest ADA side first (`big_moves.max_units`). Data: free Koios public tier, no key (5,000 requests/day, 100 per 10s, 30s query timeout, 1 KB POST body). It stays polite through shared pacing, 24h block windows only, at most `utxo_batch` (10) tx hashes per POST, a per-run `max_calls` budget (80), and a private Actions-cache file (`big-moves-cache.json`, never committed) that keeps per-token block heights so each tx is read once; a busy token is marked `capped` and resumes next run. It works at any cadence (hourly-capable); the trigger stays cron-job.org. The owner's wallet is never looked up; any owner matching the existing `PRIVACY_GUARD_PATTERNS` secret is dropped in memory before caching or writing, and the commit-time privacy guard still runs.

**Founder whale ledger (SPD-44, `whale_ledger.py`):** research rows for Snek, never triggers or the webhook. Each non-dry run writes `desk-data:solada-prefilter/whale_ledger.json` for $cockwhale (`config.json` `whale.stake`, prefix `uylu74g0`; output shows only `whale_tag`). Rows: `{time, tx_short, kind, token, qty, ada_leg, counterparty_tag}`, with `kind` one of `swap`, `lp_add`, `lp_remove`, `order_open`, `order_fill`, `order_cancel`, `transfer_in`, `transfer_out` (swaps add `direction`; order rows add `order_ref_short` and `order_status`). The file also holds running `positions` {token: raw qty}, `ada_balance` and `orders`. It is idempotent: every tx is applied at most once (deduped by full tx hash kept in the file's `_state`), the block window overlaps by one block, and positions change only from the whale's own net UTxO deltas, so a buy is never counted twice (the Oct 26 ASCEND ~2x). Every caught-up run reconciles against Koios `account_info` / `account_assets` and reports `reconcile.ada_drift` / `token_drift` (never auto-corrected). The first run is a baseline: it seeds balances from Koios and starts at the account's latest tx. DEX orders: a tx that parks a token (or 10+ ADA) at a script output holding only what the whale sent, spending no pool UTxO, opens an order (`tx#index`). A later tx spending that ref is `order_fill` (other side received) or `order_cancel` (same token back). A ref spent without the whale seeing a tx is `closed_elsewhere` (checked with `utxo_info`). Partial fills are recorded as filled. Koios public tier, no key: shared pacing, at most 10 hashes per POST, `max_txs` (100) and `max_calls` (60) per run; a backlog is marked `capped` and resumes next run. Blockfrost fallback: Koios stays primary. When a Koios call fails or times out and the `BLOCKFROST_PROJECT_ID` secret is set (passed only to the run step), the same data is read from Blockfrost (`/accounts/{stake}/transactions`, `/txs/{hash}/utxos`, `/accounts/{stake}` + `/addresses/assets`, `consumed_by_tx` for order status) under its own `max_bf_calls` (120) budget. With an empty key the fallback is skipped quietly. The key goes only in the request header and is never printed or written. `blockfrost_fallbacks` / `blockfrost_calls` are reported in the file.

**Dev checks (phase 1, `dev_checks.py`):** one row per tracked Solada launch in `desk-data:solada-prefilter/dev_checks.json`. Fields: `ticker`, `policy_short`, `dev_tag` (12 characters max: a flags/watch prefix when one matches, otherwise the `w-` hash from `flags.py`), `dev_sold_ada`, `dev_sold_after_min`, `holders_at_sell`, `late_rug`, `serial_3h`, `serial_7d`, `prior_rugs`, `ath_mcap`, `drawdown_pct`, `inactive`, `risk` (`low`/`caution`/`high`), `changed_since_last`, `asof`. `dev_buy_ada`, `dev_locked_pct` and `unlock_date` are always null (phase 2). The dev is the launch's creator stake (`launcherAddress`, or, when that address has no stake, the non-script stake that funded a verified mint tx). Rows and webhook keys are the token (policy + asset name), so a ticker that changes token starts a new baseline. The Solada curve reserve `w-f46e5a31` (`flags.exclude_tags`) is not a holder and not a seller. A sell is the creator's own key UTxOs losing the token and gaining ADA in one transaction, or ADA paid later for the filled part of tokens that key had parked at a script. A cancel (tokens come back with the deposit) is not a sell. A partial fill counts only the filled quantity. Staking-reward withdrawals in the tx are not counted as sale proceeds; the Blockfrost path reads those from `/txs/{hash}/withdrawals` only when that stake's ADA rose, and only while call budget remains. `late_rug` needs both a net drop of at least 80% from that stake's peak and tokens actually sold (including batcher fills) of at least 80% of that peak, at least 30 minutes after launch, while another non-excluded wallet still holds. Tokens moved to a lock or vesting script are not a sell, and a round trip is not a rug. The first row for a token is a baseline (`changed_since_last` false, no webhook). After that, a `dev_sell` trigger is added only for a sell tx the private cache has not seen, and only when the new sell is at least `min_sell_ada` (25 ADA, a dust floor) or `late_rug` flipped true. A public row whose sell cache is missing is re-baselined (current hashes recorded, no fire). The public fired key hashes the tx prefix; the raw hash stays in the private cache. An incomplete read is marked partial and never lowers a stored sell. The same sell does not re-fire. Koios is primary. Blockfrost (`BLOCKFROST_PROJECT_ID`, already on the run step) is used only when a Koios read fails; an empty key skips it. The job has its own `budget_s` (45) and `max_calls` (36), capped at run start + 600s, and runs before the webhook. A Koios 429 stops Koios inside this job, falls back to Blockfrost, and pauses Koios for about 60s. After that pause Koios resumes for whale_ledger and big_moves; the breaker is not tripped. Owner patterns (`PRIVACY_GUARD_PATTERNS`) are required (fail closed). A full address in a pattern also hides that address's stake, so a sibling address of the same wallet is left unknown. `dev_buy_ada`, `dev_locked_pct`, `unlock_date` and LP pulls are phase 2. Names it does not finish are listed under `coverage.skipped` and the run continues. `whale_ledger` then runs first inside the shared research window, for at most `whale_ledger.budget_s` (90), so `big_moves` cannot use the whole 240s before the ledger gets a turn. Private cache (`dev-checks-cache.json`, stake keys) stays in the Actions cache and is not written into desk-data.

**Public keys allowlist:** `scripts/privacy-public-keys.txt` lists exact public third-party keys (currently only $cockwhale) that the privacy guard masks before its generic full-key checks. Owner patterns (`PRIVACY_GUARD_PATTERNS` / `.privacy-patterns`) still apply, and an allowlist entry matching an owner pattern fails the guard.

**Review fixes (#26-#28 peer review):** research sections (big moves, whale ledger) now run after the webhook and the `state.json` / `kill_status.json` writes, inside a `research_budget_s` (240 s) time budget, and any error there, `SystemExit` included, is logged and skipped. Koios has a circuit breaker: a 429 (the public tier then blocks the IP for ~60 s) or 3 failures stops Koios calls for the rest of the run. All JSON writes are atomic (temp file + `os.replace`); a corrupt cache resets. Koios tx reads use `/tx_info` (spend inputs only; collateral and reference inputs excluded) with every POST body kept under 1 KB (also `flags.py`, which sent 25 hashes = 1,716 B). `kill_status.json` rows add `crossed` (every metric below its line; a newly crossed second metric is a change) and `data_gap`, keep a tracked name's last row (`stale`) when its unit is unknown, and seed `first_hit_at` from `kill_reported`. Big moves: a script address that carries a stake key (addr1z/addr1x pool) is a counterparty unless that stake also has a key UTxO in the tx; `ada` is the mover's net ADA only when it is the only token against ADA in the tx, else qty x price (`ada_basis`); a capped token is read newest-first next run and the scan start rotates; the cache keeps tags only. Whale ledger: the baseline seeds `seen` with the tip block, re-reads the tip and retries next run if it moved, and records `baseline_height` (a legacy baseline is treated the same way); private state moved to `whale_ledger_state.json` and `seen` is pruned to the last 2 blocks; an unread tx list marks the run `stale` and skips `closed_elsewhere` and reconcile; Blockfrost fallback ignores collateral/reference and height-filters its tx list; `basis` reports `koios`, `blockfrost` or `mixed`. Orders: a spent order whose token (99-101% of its qty) lands in a new script output that is the whale's or whose datum names the old order or the whale is `replaced` (`order_cancel` + `order_open` with `replaced_by` / `replaces`; other ADA in that tx is `transfer_in` with `via: script`), an ADA buy order returned as ADA is a cancel, a token-for-token fill logs no stray transfer, and orders at a script address carrying the whale's own stake are tracked. `flags.exclude_tags` (config) lists protocol wallets left out of `holder_concentration`, `concentration_jump` and the early-buyer cluster flags (and big-move rows); it holds the Solada curve reserve `w-f46e5a31`.

**Re-review fixes (#29 re-review):** the Koios circuit breaker is armed only inside the research window, so a 429 or failure during the rules screen or kill-line reads never blanks later reads. The research deadline is capped at run start + 720 s, `last-run.json` is also written before research, a privacy assert on `flags.json` (or a flags error, SystemExit included) skips flags.json instead of stopping the webhook, and leftover `*.json.tmp-*` files are removed at run start. `kill_status`: a previously crossed metric that is unread this run stays in `crossed`, so it never "re-crosses" and re-sends an unchanged line. Tracked rows carry `price_ada` and `decimals`. `flags.py` reads txs through `/tx_info` (404s logged) and its Blockfrost fallback ignores collateral/reference. Concentration snapshots carry a `basis`; `concentration_jump` only compares snapshots on the same basis, so adding an `exclude_tags` entry never reads as a jump. Big moves: owner patterns using `\<`/`\>` are unusable (run skipped), a capped token pages back newest-first (`max_pages_per_unit`, 4) and `big_moves.json` `coverage` reports per token `read`, `complete`, `pages`, and `gap_blocks` / `unread_txs` when something was not read. Whale ledger orders: `replaced` only when the whale signs the tx (spends one of its own key UTxOs), with any new qty, and also for datum-hash orders; a tx the whale did not sign that moves the full qty to a whale-named script is `order_moved` (with `paid_ada`); one that leaves less is a partial `order_fill` with the remainder kept open; a third party paying into a whale-stake script is a transfer, not an order. Reconcile reads the tip before and after the balances and is skipped (`reconcile_skipped`) when the tip moved past the applied height. Counterparty tags are never given to wallets matching `PRIVACY_GUARD_PATTERNS`, and none are given when those patterns are missing or unusable. Ledger state (tx hashes, order refs, raw positions) now lives only in the private Actions cache (`whale-ledger-state.json` in the prefilter cache dir), not in desk-data; rows are kept only in the public file. The desk-data `whale_ledger_state.json` written by #29 is read once for migration and never written again (it is not deleted).
